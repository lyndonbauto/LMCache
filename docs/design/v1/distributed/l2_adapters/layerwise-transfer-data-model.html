The realistic band is 3–104, usually under 50. Nothing served activates hundreds of billions per token, and prefill can activate less than decode. Values far above ~104 describe a dense model nobody runs — useful as a limit, not a target.

KV geometry is per model too: gpt-oss is 8×64 over 36 layers (72 KiB/token), Llama 3.1 405B is 8×128 over 126 (504 KiB/token). For MLA switch Payload format to NL_X_NB_BS_HS and set 9×64 — one 576-wide latent per token per layer, no separate K and V.

Shape at this point

The model's layers

Kernel groups bundle into object groups

An object group is what actually gets stored and keyed. It contains one or more kernel groups, laid out back to back in kernel_group_indices order.

One object per (chunk, object group)

No layer coordinate exists here. ObjectKey carries object_group_id and nothing finer, so “layer 7 arrived” can never be answered by a key. It has to be derived from byte ranges inside a payload.

CacheBlend what changes, and what does not

Which chunks of the prompt each route can reuse. Green is a plain cache hit; gold is a chunk that was cached at a different position and had its keys re-rotated to fit this one.

The two data paths

Green steps are shared code, so the RDMA work reaches them with no blend-specific effort. Red steps move every layer of a kernel group in one operation — note that both routes are red there.

So does pipelining actually help blend?

“Recompute” is the fraction of tokens the GPU calculates from scratch instead of taking from cache — so it measures how much of the prompt blend failed to reuse. Blend picks the tokens where cached KV would hurt most and recomputes only those. Lower is better: 15% is the published operating point, and 100% means nothing was reused, which is just a full prefill. Re-RoPE is not recompute — rotating a reused key is cheap, and it applies to the tokens we keep.

Same bytes on the wire either way, less compute to hide them behind, because deleting compute is the entire point of blend. Drag Blend recompute in the sidebar.

Blend reads its object groups in two legs

It issues two prefetches, and they ask for different object groups. This is driven by Architecture and --separate-object-groups in the sidebar.
