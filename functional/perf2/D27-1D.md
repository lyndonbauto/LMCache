# prototype-stage-1d: Simon's D-27 with the pool cap and the unregister wait

Valentyn, Slack 2026-10-07 20:08 UTC: "use Simon's branch as the base and port
two things from 1c: 1. Cap his loading pool at `pipelined_window_count()` ...
2. The unregister wait, plus the token priority if the server-side ordering
turns out to matter. Then rerun the c=16 and c=32 layerwise points ... push as
new branch `prototype-stage-1d`".

Verdict: the lw full-hit failures of the merged build are gone. Every request
of every point succeeded and was pipelined, with no window refusals, whole-load
timeouts or retrieve aborts in the LMCache logs. TTFT is within run-to-run
noise of 1c (one run per point).

## Branch

`prototype-stage-1d` = `df919802` (the merge of `prototype-stage-1b-2` into
`prototype-stage-1b` from [MERGE-1B-2.md](MERGE-1B-2.md)) + `f1d1a2c9`:

1. **Pool cap.** The layerwise retrieve pool has
   `StorageManager.pipelined_window_count()` threads (Simon's 32 when there are
   no RDMA windows). A retrieve past the window count waits for a thread
   instead of being refused a window and falling back to a whole load under
   the 1.5 s L1 timeout. The pool is FIFO and retrieves are admitted in
   generation order, so a waiting retrieve is newer than every running one and
   nothing it waits for waits on it.
2. **Unregister wait (D-28).** Releasing a worker calls
   `RetrieveLaunchSequencer.stop_all()` (new: stops every in-flight retrieve,
   including the newest), then waits for the worker's retrieves on the pool
   (`InflightRetrieves`, up to `layer_timeout_seconds +
   whole_load_timeout_seconds`) before closing its cache context.
3. **Token priority: not ported.** Each fetch already asks the server for
   layer 0 first, and Simon's sequencer launches layer-major across retrieves,
   the order vLLM's forward pass consumes them. 1c's request-major priority
   (all of the oldest retrieve first) would delay the newest retrieve's
   layer 0, which the step also waits on.

Design doc: `docs/design/v1/multiprocess/layerwise-load.md`, "Concurrent
retrieves per worker".

## Tests (HIP build on the MI300X, `lmc-c`)

- The 7 changed test files: 79 pass, 5 repeat runs. New tests:
  - a retrieve past the window count waits for a thread;
  - with no windows, retrieves load at once;
  - unregister stops a loading retrieve and closes the cache context only
    after it ends;
  - unregistering an idle worker publishes no failure;
  - `stop_all` stops the newest retrieve too;
  - `stop_all` with nothing in flight changes nothing.
- `tests/v1/multiprocess` + `tests/v1/layerwise`: 1393 pass. The 6 failures
  and 16 errors are the same set as on the merged build: gRPC protobuf
  modules missing in the container, and tests still expecting register to
  return None (already failing on 1b).
- ruff and mypy clean on the changed files.
